# useRequest → SWR 迁移指南（EasyAPI 实际形态）

> ⚠️ **版本说明**：本文档已按本项目实际代码形态重写。此前版本假设的 `useRequest(url, { method })` 形态与本项目不符（本项目是 ahooks 函数式签名），照旧文档迁移会失败，请以本文为准。
>
> 适用场景：Next.js 16 + React 19 + SWR 2.x，项目中使用自实现 `useRequest(service, options)`（`src/hooks/use-request.ts`），迁移到 [SWR](https://swr.vercel.app) 以获得稳定缓存、去重与竞态保护。

---

## 一、本项目现状（迁移前必读）

### 1.1 hook 签名

```ts
// src/hooks/use-request.ts
useRequest<T, P extends unknown[] = []>(
  service: (...args: P) => Promise<T>,   // 业务函数，URL/请求方式已封装在调用方或 services 层
  options?: { manual?, defaultParams?, onBefore?, onSuccess?, onError?, onFinally? },
) => { data, loading, error, run }
```

关键点：

- 第一个参数是 **service 函数**，不是 URL；`run(...args)` 原样透传给 service。
- `manual: true` 时挂载不请求，靠外部 `run(...args)` 触发；否则挂载自动执行一次。
- 内置 requestId 竞态保护（丢弃过期响应）+ 模块级进度条计数（并发时只有第一个 start、最后一个 stop）。
- `run` 失败 **不向外抛错**（catch 后只进 `error` 状态与 `onError` 回调）。

### 1.2 请求层（`src/lib/request.ts`，迁移时保留不动）

```ts
httpRequest.get/post/put/delete<T>(url, data?, config?) => Promise<App.IResponse<T>>
// IResponse = { code, data, msg, timestamp }
```

- 网络错误 / HTTP 非 2xx：`throw`；
- 业务失败（`code !== 200`）：仅 `toast.danger` 提示，**正常 resolve**，由调用点自行判断。

### 1.3 调用点分布（32 个 / 28 个文件）

| 形态 | 数量 | 位置 | 特征 |
|---|---|---|---|
| 自动查询 + 点击刷新 | 21 | 工具页 ClientComponent | 内联 service 包 `getApiData(pathname, params)`，`run` 无参用于按钮/刷新，`error` 传给 RequestContent |
| 自动查询（共享组件） | 3 | QuoteWorld / JsonContent / UserAvatar | 同上，被 12+ 页面复用 |
| 手动带参（admin） | 6 | apis、categorys 的列表 + 2 个 save-modal + 2 个删除 | `manual: true` + 单参 `run` + `onSuccess` 里 `code === RESPONSE.SUCCESS` 判断 |
| 特殊（原生 fetch） | 2 | barcode / qrcode | service 内直接 `fetch` 图片二进制，`onSuccess` 写外部 state，不消费 `data` |

已确认：**无上传 / FormData 请求、无多参 run、无跨组件共享数据（`/auth/me` 仅 UserAvatar 一处）、`onError` / `onFinally` 全项目零使用**。

## 二、为什么迁移

| 问题 | 手写 useRequest | SWR |
|---|---|---|
| 竞态条件 | 手写 requestId 丢弃过期响应（能用，但需自维护） | 内置请求时序保证，过期响应不写入 |
| 缓存 / 去重 | 无缓存，每次挂载都请求 | 同 key 并发去重 + 全局缓存 |
| 分页体验 | 翻页时 `data` 清空，列表闪空 | `keepPreviousData` 翻页保留旧数据 |
| 写操作后刷新 | 手动 `run` + 回调 | `mutate()` 强制重新验证，不受去重限制 |
| 自维护成本 | `use-request.ts` 约 130 行（竞态 + 进度条计数） | 全部交给 SWR |

**诚实评估**：本项目 25/32 调用点是"点按钮取一次数据"的工具页，缓存/去重增量收益有限；核心收益是 **admin 分页不闪空**、**少维护 130 行**、**统一数据层**（后续 `/auth/me` 等可共享缓存、可开焦点重验证）。

## 三、方案选型

| 维度 | 手写 useRequest | **SWR** | TanStack Query |
|---|---|---|---|
| 体积增量 | 0 | ~4KB gzip | ~13KB gzip |
| 竞态保护 | 手写 requestId | ✅ 内置 | ✅ cancel + 最新优先 |
| 缓存 / 去重 | 无 | ✅ | ✅ 更强 |
| 写操作 | 手动 run | `useSWRMutation` | mutation 一等公民 |
| 与 Next.js 生态 | — | **Vercel 官方** | 通用 |
| 迁移成本 | — | 低 | 中 |

**结论**：本项目请求模式简单（列表查询 + 少量写操作），选 SWR。TanStack Query 强在乐观更新 / 无限查询 / 复杂缓存失效，中大型数据密集型后台才值得。

## 五、核心代码（可直接复制）

### 5.1 底层请求封装（保留）

`src/lib/request.ts` 与 `src/services/*` **一行不改**：service 函数（`delApi`、`updateApi`、`addApi`、`getApisList` 等）已封装好 URL / 请求方式 / 参数拼装，SWR 直接复用。

### 5.2 `src/lib/swr.ts`

```ts
import type { SWRConfiguration } from 'swr'

/**
 * 全局 SWR 配置：平替原 useRequest 行为
 * - 关闭窗口聚焦 / 断线重连自动刷新（原实现无此行为）
 * - 失败不重试（httpRequest 网络错误直接 throw，业务失败仅 toast，均无需重试）
 * - throwOnError: false —— 等价原 run：请求失败不向外抛错，只进 error 状态 / onError 回调
 */
export const swrConfig: SWRConfiguration = {
  revalidateOnFocus: false,
  revalidateOnReconnect: false,
  shouldRetryOnError: false,
  throwOnError: false,
}
```

> 本项目调用点解包深度不一（`'data'`、`'data.list'`、`get(..., 'data', null)`），所以**不提供统一 fetcher**，每个调用点用闭包 fetcher 精确解包（见第六节）。没有全局 fetcher 反而少一层抽象。

### 5.3 `src/hooks/use-swr.ts`

```ts
'use client'
import { useProgress } from '@bprogress/next'
import { useEffect } from 'react'
import useSWR from 'swr'
import useSWRMutation from 'swr/mutation'

import type { Key, SWRConfiguration } from 'swr'
import type { SWRMutationConfiguration } from 'swr/mutation'

// 模块级进度计数：全局进度条是共享资源，多个 hook 实例并发时
// 只有第一个请求 start、最后一个完成 stop（与原 use-request.ts 语义一致）
let progressCount = 0

/** 进度条同步：active 为 true 期间持有进度条，多个实例并发互不打断 */
function useProgressSync(active: boolean) {
  const { start, stop } = useProgress()

  useEffect(() => {
    if (!active)
      return
    if (progressCount === 0)
      start()
    progressCount++
    return () => {
      progressCount = Math.max(0, progressCount - 1)
      if (progressCount === 0)
        stop()
    }
  }, [active, start, stop])
}

/**
 * 查询 hook：平替原 useRequest 自动模式（挂载自动请求）
 * - fetcher 为闭包：捕获调用点最新参数；key 固定时，点击刷新用 mutate()（mutate 不受 dedupingInterval 限制）
 * - loading = 首次加载或任何重新验证进行中（等价原 loading）
 */
export function useSwrQuery<T = unknown>(
  key: Key,
  fetcher: (key?: Key) => Promise<T>,
  options?: SWRConfiguration<T>,
) {
  const result = useSWR<T>(key, fetcher, options)
  useProgressSync(result.isValidating)

  return {
    ...result,
    loading: result.isLoading || result.isValidating,
  }
}

/**
 * 写操作 hook：平替原 useRequest(manual: true) 的 run
 * - service 直接复用现有 services 层函数（如 delApi、updateApi），不改业务代码
 * - trigger(arg) 等价原 run(arg)，失败不抛错（throwOnError: false）
 * - ⚠️ mutation key 不要与查询 key 相同，用 `${url}:save` / `${url}:delete` 等后缀区分
 */
export function useSwrMutation<T = unknown, A = unknown>(
  key: string,
  service: (arg: A) => Promise<T>,
  options?: SWRMutationConfiguration<T, Error, string, A>,
) {
  const result = useSWRMutation<T, Error, string, A>(
    key,
    (_key, { arg }) => service(arg),
    { throwOnError: false, ...options },
  )
  useProgressSync(result.isMutating)

  return {
    ...result,
    loading: result.isMutating,
  }
}
```

> 说明：`service` 类型为通用的 `(arg: A) => Promise<T>`（`T` 是 service 返回值，如 `App.IResponse<App.Api>` 或 barcode/qrcode 的图片 URL 字符串），比强制 `IResponse<T>` 更通用，`error` 泛型固定为 `Error`（与 RequestContent 的 `error: Error | undefined` 匹配）。

> **loading 语义**：查询用 `isLoading || isValidating`（首次加载或任何重新验证进行中）；写操作用 `isMutating`。工具页手动 `mutate()` 时 `isLoading` 为 false（已有缓存）、`isValidating` 为 true —— 合并后等价原 `run` 期间的 loading。

## 六、调用点改写对照

### 6.1 工具页 / 共享组件（自动查询 + 点击刷新，23 处，同构批量改）

以 QuoteWorld 为例（21 个工具页 + JsonContent / UserAvatar 同套路）：

```tsx
// 原（src/components/QuoteWorld/index.tsx）
const { data = {}, loading, error, run } = useRequest(
  async () => get(await getApiData(pathname), 'data', {}),
  {
    onBefore: () => {
      setShowFormContent(false) // 每次请求前重置 UI
    },
  },
)
// <RequestContent ... reFresh={run} />  <RefreshButton loading={loading} text="换一句" onPress={run} />

// 新
const { data = {}, loading, error, mutate } = useSwrQuery(
  pathname, // key 固定：闭包 fetcher 里读最新 pathname / params
  async () => get(await getApiData(pathname), 'data', {}),
)
// onBefore 的 UI 重置逻辑移到刷新入口：
const handleRefresh = () => {
  setShowFormContent(false)
  mutate() // 强制重新验证，参数通过闭包自动拿最新值
}
// <RequestContent ... reFresh={handleRefresh} />  <RefreshButton loading={loading} text="换一句" onPress={handleRefresh} />
```

要点：

- **key 固定为 pathname，参数走闭包**：输入框/选择器变化不触发请求（保持原"点击才请求"语义），点击时 `mutate()` 用最新闭包重新请求。
- `mutate()` 不受 `dedupingInterval` 限制，连续点击都会发请求。
- 挂载自动请求一次（SWR 默认行为，等价原自动模式）。
- 原 `onBefore` 的 UI 重置逻辑挪到刷新入口；挂载首次请求无需重置（初始 state 已是初始值）。

JsonContent 同样（注意泛型从 2 个简化为 1 个）：

```tsx
// 原（src/components/JsonContent/index.tsx）
const { data, loading, error, run } = useRequest<T, (typeof params)[]>(
  async () => get(await getApiData(pathname, params), 'data'),
)
const reload = () => {
  const flag = onRefresh()
  if (flag) {
    run()
  }
}

// 新
const { data, loading, error, mutate } = useSwrQuery<T>(
  pathname,
  async () => get(await getApiData(pathname, params), 'data'),
)
const reload = () => {
  const flag = onRefresh()
  if (flag) {
    mutate()
  }
}
```

```tsx
const { mutate } = useSWRConfig()

await supabase.auth.signOut().then(() => {

```

### 6.3 admin 分页列表（最复杂，apis / categorys 两个 index.tsx）

原实现：`manual: true` + `useEffect(() => run(searchParams), [run, searchParams])` 由 React Table 的 `pagination` 驱动。迁移后：**搜索/分页参数作为 key 的一部分，key 变化自动请求，删掉 useEffect**：

```tsx
// 原（src/app/admin/components/apis/index.tsx）
const { data, loading, run } = useRequest(async params => get(await getApisList(params), 'data', {}), {
  manual: true,
  defaultParams: [searchParams],
})
useEffect(() => {
  run(searchParams)
}, [run, searchParams])

// 新
const { data, loading, mutate } = useSwrQuery(
  ['/apis', searchParams], // key 含参数：搜索/分页变化自动请求
  async () => get(await getApisList(searchParams), 'data', {}),
  { keepPreviousData: true }, // 翻页保留旧数据，不闪空
)
// 删掉原来的 useEffect(() => run(searchParams), ...)

// 查询：搜索词与分页都没变时 key 不变，SWR 不会发请求 → 手动 mutate()
const handleSearch = () => {
  setQuery({ name, category_id: categoryId })
  setPagination(p => (p.pageIndex === 0 ? p : { ...p, pageIndex: 0 }))
  if (name === query.name && categoryId === query.category_id && pagination.pageIndex === 0) {
    mutate()
  }
}

// 重置：同样处理"重置后 key 没变"的情况
const handleReset = () => {
  setName('')
  setCategoryId('')
  setQuery({ name: '', category_id: '' })
  setPagination({ pageIndex: 0, pageSize: 10 })
  if (query.name === '' && query.category_id === '' && pagination.pageIndex === 0) {
    mutate()
  }
}
```

要点：

- `searchParams` 是 `useMemo(() => ({ ...query, ...pagination }), [query, pagination])`，引用稳定，key 只在 query / pagination 变化时变。
- 快速翻页 = key 变化，SWR 保证旧请求结果不覆盖新 key 数据（竞态安全）。
- 删除 / 保存成功后的 `handleSearch()` / `handleRefresh()` 自动落到上面的"参数未变 → mutate()"分支，列表必然刷新。
- 分类下拉（`getCategorysList` 自动模式 + `defaultParams`）同样迁移：key 编码参数或闭包，例如：

```tsx
// 原
const { data: categorysList } = useRequest(async params => get<App.Category[]>(await getCategorysList(params), 'data.list', []), {
  defaultParams: [{ pageIndex: 0, pageSize: 999 }],
})
// 新
const { data: categorysList } = useSwrQuery(
  '/categorys:list', // 固定 key + 独立前缀，避免与列表查询 key（['/categorys', params]）深度相等时互相覆盖缓存
  async () => get<App.Category[]>(await getCategorysList({ pageIndex: 0, pageSize: 999 }), 'data.list', []),
)
```

```tsx
// 原（src/app/admin/components/apis/index.tsx）
const { loading: delLoading, run: fetchDelApi } = useRequest(delApi, {
```

### 6.5 保存（POST / PUT）

```tsx
// 原（src/app/admin/components/apis/components/save-modal.tsx）
const { loading, run } = useRequest(initialValues?.id ? updateApi : addApi, {
  manual: true,
  onSuccess: ({ code }) => {
    if (code === RESPONSE.SUCCESS) {
      state.close()
      toast.success('提交成功', { timeout: 2000, indicator: <CircleCheckFill /> })
      handleRefresh?.()
    }
  },
})
// onSubmit: run(data)

// 新
const { loading, trigger } = useSwrMutation(
  '/apis:save',
  (data: App.ApiSaveParams) => (initialValues?.id ? updateApi(data) : addApi(data)),
  {
    onSuccess: ({ code }) => {
      if (code === RESPONSE.SUCCESS) {
        state.close()
        toast.success('提交成功', { timeout: 2000, indicator: <CircleCheckFill /> })
        handleRefresh?.()
      }
    },
  },
)
// onSubmit: trigger(data)
```

要点：service 是三元选择时，把判断放进闭包（每次 trigger 用最新 `initialValues`，SWR 内部 ref 保持最新 fetcher）。`updateApi({ id, ...params })` 需要 `data` 含 id，与原来一致。

### 6.6 特殊：barcode / qrcode（原生 fetch，已迁移）

`service` 内直接 `fetch` 图片二进制、`onSuccess` 写外部 state（`imgSrc` / `downloadUrl`）、不消费 `data`。迁移用 `useSwrMutation`（手动触发语义）+ 挂载时 `useEffect` 自动触发一次（等价原自动模式）：

```tsx
// 原：useRequest(service, { onSuccess: 写 imgSrc/downloadUrl })
// 新
const { loading, error, trigger } = useSwrMutation(
  `${pathname}:generate`, // mutation key 加后缀，避免与其他查询 key 冲突
  async () => { /* 原生 fetch 逻辑不变，返回图片 URL（string | null） */ },
  {
    onSuccess: (res) => {
      if (res) { /* 原 onSuccess 逻辑：revoke 旧 blob + setImgSrc + setDownloadUrl */ }
    },
  },
)

// 挂载自动生成一次（等价原自动模式）
useEffect(() => {
  trigger()
  // eslint-disable-next-line react/exhaustive-deps -- 仅挂载时生成一次，后续由 reFresh 显式触发
}, [])
```

### 6.7 `run` → 新 API 速查

| 原 | 新 | 说明 |
|---|---|---|
| `useRequest(service, { manual: true })` | `useSwrMutation(key, service)` | key 用 `${url}:save` / `:delete` 后缀，勿与查询 key 相同 |
| `run(args)` | `trigger(args)` | 失败不抛错（`throwOnError: false`） |
| `useRequest(service)` 自动 | `useSwrQuery(key, fetcher)` | fetcher 闭包精确解包 |
| `run()` 手动刷新（工具页） | `mutate()` | key 固定 + 闭包读最新参数 |
| `defaultParams` | key 编码参数 / 闭包 fetcher | 见 6.3 分类下拉 |
| `onBefore` | 移到刷新入口 | 见 6.1 |
| `onSuccess(data, params)` | `onSuccess(data)` | SWRMutation 回调签名为 `(data, key, config)`，只取 data 即可 |

## 七、踩坑记录（务必阅读）

### SWR 通用

1. **数组 key 整体传给 fetcher**：`useSwrQuery(['/apis', params], fetcher)` 中 fetcher 收到的唯一参数是整个数组，不是展开的两个参数。闭包 fetcher 忽略该参数、直接用闭包变量即可；若用统一 fetcher 需自行解构。
2. **参数未变时点击"查询"不发新请求**（key 深度相同 + `dedupingInterval` 缓存命中）。→ `handleSearch` 里比较新旧参数，未变时 `mutate()`（见 6.3）。
3. **`dedupingInterval` 默认 2000ms**：同 key 2s 内重复请求复用缓存。删除 / 保存后的刷新走 `mutate()`，**不受**该限制，列表一定能刷新。
4. **翻页闪空**：SWR 默认 key 变化后 `data` 变 `undefined` → 列表查询必须加 `{ keepPreviousData: true }`（SWR ≥ 2.1）。
5. **mutation fetcher 第二参是 `{ arg }`**：`trigger(extraArg)` 传入的值即 `arg`。本方案 service 直接复用现有函数，`trigger(args)` 原样透传。

### 本项目特有

6. **⚠️ mutation key 不能与查询 key 相同**：`useSwrMutation('/apis', ...)` 与 `useSwrQuery(['/apis', ...], ...)` 会互相污染缓存（查询读到的 data 可能被 mutation 的返回覆盖）。用 `${url}:save` / `${url}:delete` 区分。
7. **`trigger` 默认 rethrow**：原 `run` 失败不抛错。已通过全局 `throwOnError: false` + hook 内显式合并关闭，但**新增 mutation 调用点时不要手动传 `throwOnError: true`**。
8. **loading 映射**：手动触发（工具页 `mutate()`、写操作 `trigger()`）时 `isLoading` 是 false，必须用 `isValidating` / `isMutating`（hook 已合并进 `loading`，调用点无需改动）。
9. **进度条并发计数不能丢**：多个 hook 实例并发时若各自 start/stop 会互相打断进度条。`use-swr.ts` 已保留模块级计数，新增 hook 请复用 `useProgressSync`，不要在调用点自己调 `useProgress`。
10. **业务失败会被 SWR 缓存**：`httpRequest` 对 `code !== 200` 仅 toast、正常 resolve，SWR 会把"业务失败结果"当成功缓存。本项目默认接受（工具页每次点击都 `mutate()` 重新验证；admin 列表参数不同 key 不同）；若某接口必须"每次挂载都重新请求"，在 fetcher 内对 `code !== 200` 抛错（配合 `shouldRetryOnError: false`）。mutation 同理：`trigger` 返回的业务失败结果（`code !== 200` 的 IResponse）也会被 `useSWRMutation` 缓存，`onSuccess` 判断 `code` 时读的是本次响应不受影响，但若后续直接读 `data` 需留意可能是上次失败结果。
11. **类型坑**：`SWRMutationConfiguration` 从 **`swr/mutation`** 导出；没有 `SWRMutationKey` 导出类型，mutation key 直接限定为 `string`。
12. **`react/set-state-in-effect` lint**：6.3 迁移后已删除分页驱动 `useEffect`，不再触发该规则；若保留类似 effect，需要行内 `eslint-disable-next-line` + 说明。
13. **会话相关接口（`/auth/me`）要主动清缓存**：迁移后 `/auth/me` 的 `isAdmin` / `email` 进入 SWR 全局缓存（它控制"管理后台"入口显示）。登出 / 切换账号 / 管理员被降权后若不清缓存，`UserAvatar` 会展示旧会话的权限与邮箱。缓解：登出流程里 `useSWRConfig().mutate('/auth/me', null)` 清除该 key，或 key 按会话派生（如 `['/auth/me', userId]`，登出后 userId 变化自然失效）。

- [ ] 顶部进度条并发行为不变（模块级计数）

**有意差异（确认接受）**：

- 挂载时同 key 会读缓存（原实现每次挂载都发请求）——这是缓存带来的预期行为；

- `/auth/me` 等会话相关接口会命中缓存，登出 / 降权后需显式清缓存（见踩坑 13）。
