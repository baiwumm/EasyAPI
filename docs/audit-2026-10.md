## 关键修复的技术要点

这些是「照抄会踩坑」的部分，改动前先读懂。

### B5：空值检查必须在净化之后

`sanitizeLikeKeyword()` 会删除 `, ( ) " \` 这些 PostgREST `or()` 语法字符，
所以 `?keyword=,` 净化结果是**空串**。原本 `if (!keyword)` 在净化前执行，
拦不住这种输入，拼出的 `province.ilike.%%` 匹配全表。

正确写法：净化后复查空串，且必须在 `getSupabaseServerClient()` **之前**返回
——测试里用 `expect(supabase.from).not.toHaveBeenCalled()` 钉住这一点。

### C1：不泄露 ≠ 不留痕

新增 `dbErrorResponse(error, label)`：原文进 `console.error`（带 label），
对外只返回固定文案「服务开小差，请稍后重试」。仅管理端路由保留原文
（已过 `requireAdmin()`，排查需要）。

### B3：`getJieQiList()` 返回跨年区间

`Lunar.fromYmd(y,1,1).getJieQiTable()` 覆盖上年 12 月到次年 3 月共 31 项，
需按 `getYear() !== year` 过滤才是请求年份的 24 个节气。
文件里保留的 `solarTermEnum` 只映射 7 个英文字段名，其余靠 key 原样输出——
过滤后不再出现英文常量名。

### D2：已提交参数模式

统一为 `useCommittedParams` + `[pathname, params]` 作为 SWR key：

- 输入框变化只更新本地 state，**不进 SWR key**，不触发请求；
- 点「查询/生成」时 `commit(params)`，参数变了 key 才变，自动重查；
- 参数没变时 `commit` 返回 `false`，退回 `mutate()` 手动刷新。

SWR 对 array key 做 `stableHash`，结构相等的对象哈希相同，
所以调用点每次渲染新建的 `params` 对象不会造成无限请求。

### 测试里钉住的「现状即正确」行为

有几处实现行为不符合直觉，当时选择**在测试中钉住并注释**而非改实现，
避免在测试任务中混入行为变更。改动前先看这些注释：

| 位置 | 行为 |
|---|---|
| `parseBoundedInt("1e3",1,1,100)` | `parseInt` 截断得 1，不是 1000 |
| `parseBoundedInt("1eee",...)` | 截断得 1，被 min 兜住，至少不是 NaN |
| `clamp(NaN, 1, 20)` | 仍是 NaN，所以不能用它兜 `parseInt` |
| `get("s","length",0)` | 字符串也能按 key 取值，返回 1 |
| `getUrl(_UHD.jpg 输入)` | 双重拼接出 `..._UHD.jpg_1920x1080.jpg`（未修，见 backlog C9） |
